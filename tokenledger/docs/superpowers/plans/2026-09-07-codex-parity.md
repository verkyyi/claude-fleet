# Codex 采集与展示补齐方案

日期：2026-09-07。状态：主体实现、生产迁移与全部节点部署验收完成。最终版本：`7db2bda-codex-parity.3db23eba8cf4`。

目标：让 Codex 在 ccquota 中拥有与 Claude 同等级的账户、额度、实时状态和用量分析体验，并让后续来源可以复用采集、存储与展示能力。

## 2. 采集与数据设计

### 2.1 延续统一数据模型，增加来源适配层

保留现有增量扫描、持久化队列、重试和 hub 聚合。把来源相关工作收敛为读取用量、识别账户、读取额度、读取实时状态四类能力，各适配器声明支持情况。

`source=codex` 表示客户端来源。另设 `model_provider` 和 `billing_mode`，区分 OpenAI、其他服务商，以及订阅/API/未知计费模式，避免将所有 Codex 日志默认套用 OpenAI 订阅额度或价格。

新增或扩展以下数据：

- 来源实例：`endpoint_id + source + profile_id`，记录 Codex home、客户端版本、当前账户、能力和健康状态。目录路径只在本地使用，hub 保存不含敏感路径的实例标识。
- 账户归属记录：来源实例/会话/时间范围、账户标识、归属依据与可信程度。同一 OS 用户可以同时使用多个配置目录和账户。
- 通用额度快照：`source + account + quota_scope + limit_id`，保存窗口时长、已用百分比、重置时间、采样时间、数据来源，以及可用时的 credits 和额度耗尽原因。
- 实时会话：增加 `source`、来源实例、账户、活动状态、观测时间和字段可用性；费用、上下文缺失不能默认为 0。
- 来源健康：分别记录最近扫描、最近事件、额度查询、心跳、队列积压与失败原因。空目录、未安装、暂时空闲、无权限和解析失败有不同展示。

既有 Claude 数据保持旧协议兼容，新字段采用可选或明确的未知状态。额度窗口不能继续把所有来源强制映射成固定的 5 小时和 7 天。

### 2.2 账户与额度来源

Codex App Server 提供 `account/read`、`account/rateLimits/read`、`account/rateLimits/updated` 和 `account/usage/read`。额度返回窗口长度、已用比例、重置时间和可能存在的多个额度池；账户用量可以返回累计值与每日桶，字段可能为空，API-key-only 模式不支持该账户用量接口。[OpenAI Docs：App Server](https://learn.chatgpt.com/docs/app-server)

接入顺序：

1. 被动读取日志中已有的 `rate_limits`，保留事件原始采样时间。回放历史快照不能被当作当前读数，也不能因 token 计数未增加而丢掉额度更新。
2. 用官方账户接口补当前身份、套餐和空闲期间的额度。优先复用已有 Codex 进程的可用连接；独立 helper 必须先验证凭据存储兼容、超时退出和登录刷新行为，避免与正在工作的客户端争用登录状态。
3. 身份采用服务端给出的稳定标识；验证它代表个人、工作区还是工作区成员的额度范围。信息不完整时保留来源实例级的未确认账户，并允许显式映射。邮箱、套餐和重置时间不足以证明是同一额度池。
4. 新采集数据按会话及当时的账户关联归属。历史 `codex:local` 默认保留，仅按可验证证据或明确的人工映射关联已有记录。
5. 同一额度池的多机器快照按观测时间选用并保留观测来源，百分比不相加。轮询加入间隔与随机抖动；每个账户优先由一个在线采集端负责查询，其他采集端的被动观测仍可上报。

额度百分比直接显示服务端读数。按机器分摊和耗尽时间均为估算；只有账户、时间窗口和计费模式匹配、计价覆盖足够时才展示。数据不足时展示原因。

### 2.3 实时状态

默认复用现有文件监听：解析 `task_started`、`task_complete`、`turn_aborted` 及用量更新，形成活动状态和累计计数，并上报到现有 Live/SSE 通路。初次回填与重启恢复必须按原始时间判断状态，不能把历史会话显示为正在运行。

无法持续确认存活的日志状态显示“最近活动”，保留最后观测时间；明确的完成/中断事件立即结束活动状态。长期无新增 token 不足以判断任务已完成，长工具调用应通过受支持的生命周期事件补充。

官方 Hooks 支持开始、提示提交、工具执行、停止和中断等生命周期事件，可作为已有文件监听的补充。Hook 只写少量本地状态，agent 异步发送，监控故障不影响任务。[OpenAI Docs：Hooks](https://learn.chatgpt.com/docs/hooks)

App Server 通知仅用于能访问的现有会话连接；启动一个新 app-server 不能被假定为可以旁听所有既有 GUI/CLI 会话。等待审批等精细状态按实际可观测能力展示。

上下文使用率使用最新请求/压缩后上下文与模型容量，不能使用会话累计消耗除以容量。token/min 基于实测差值；累计心跳和持久化用量不能重复加入总数。

### 2.4 费用与 token 分类

先覆盖 fleet 实际使用且有官方价格的模型；本机样本包括 `gpt-6-astra`、`gpt-5.6-sol` 和 `gpt-5.6-terra`。费率需要版本、生效区间、来源链接、缓存输入/写入和服务档位，不能只加一个统一单价。当前公开价格还区分上下文档位与处理速度。[OpenAI API 定价](https://developers.openai.com/api/docs/pricing)

新增中立的缓存写入计数，核对它与输入总数的包含关系。Claude 的 5 分钟/1 小时 TTL 分类继续保留；Codex 没有 TTL 信息时不强行分配。推理 token 仍是输出的子集。

展示区分“API 标价折算”“服务端返回的 credits/用量估算”和“实际账单”。订阅额度、credits 与美元计费分别处理；本地 token 日志不能单独恢复实际账单。影响额度的因素还包括模型、上下文、工具和缓存。[OpenAI Docs：定价与额度](https://learn.chatgpt.com/docs/pricing)

未知模型继续显示未计价。缺少档位、实际模型或缓存字段时显示折算依据/覆盖范围。费率补充后，在现有记录上回算可确定的费用；已裁剪原始记录的历史不能伪造缺失字段。

### 2.5 历史与服务端总量对账

将 `account/usage/read` 的账户汇总保存为独立观测数据，展示“服务端账户活动总量”和“已采集端的本地用量明细”。先验证时间边界、时区、更新延迟和覆盖范围是否可比，再提供差额或覆盖提示。

服务端总量与本地明细存在重叠，不能相加。差额不能直接认定为云任务或丢失数据。仅有账户总量不能还原未采集云任务的项目、会话和机器明细。

## 3. 界面结果

- Now 和 Review 共用来源选择：全部 / Claude Code / Codex；账户选项随来源联动。各额度池单独展示，来源不匹配的账户不会留下混合读数。
- Now 展示账户/套餐、额度进度、重置时间和数据更新时间，下方是 Codex 活跃或最近活动会话、机器、项目、模型、token/min 与上下文。
- Review 延续现有时间线和分组，增加费用覆盖、缓存写入、任务与请求计数说明、Codex 额度历史和可比时的服务端对账。
- Fleet 对每个 endpoint 展示 Claude/Codex 各自的采集状态和客户端版本，便于判断“没有用量”还是“采集有问题”。
- quota history、findings、Live、MCP、预算查询全部使用同一来源/账户语义。额度不随项目/机器筛选变成局部真实额度；相应筛选只用于明细或标明估算的分摊。

## 4. 分批交付与验收

| 批次 | 工作内容 | 可验收结果 |

| 第三批：对账与预算 | 账户用量观测；可比范围对账；额度趋势与诊断；`budget --source codex`；MCP 对齐 | 同范围可对账且不重复计数；预算使用对应来源/账户的最紧有效窗口及耗尽状态；未知数据沿用现有 unknown 语义 |

每批的验收覆盖以下有实际风险的场景：

- 旧/新日志格式、只有额度变化的事件、文件归档/复制、重启、离线重放和队列失败；token 不丢失、不重复。
- 一个用户多配置目录、多个账户并行、跨机同账户、切换登录与历史回填；当前身份不重写无法证明归属的旧记录。
- 缺失窗口、多个额度池、窗口重置、乱序快照、过期认证、API-key-only、非 OpenAI provider；未知值不显示为 0% 或免费。
- 来源选择后，Now、Review、额度历史、findings、MCP 和 budget 的结果一致。
- 生产库备份上演练迁移，比较原始用量与小时汇总；保留已裁剪原始数据对应的历史。

当前去重键含 `account_uuid`。账户关联或补字段不能简单将原事件换账户后重新 ingest；应通过稳定的原始事件标识更新已有记录，或使用独立归属映射，并验证总事件数和 token 不变。

首批实现前，将 mini 0.149.0 和 MacBook 0.153.4 的实际协议能力列为兼容基线。mini 的 Homebrew CLI 依赖正确的 Node/PATH，LaunchDaemon 环境也必须单独验证。协议采用能力探测和降级；基础日志采集不依赖账户 API 一定可用。

发布继续使用先升级 mini hub、再选择一个有 Codex 数据的 mini agent 验证、最后升级其余 agent 的顺序。每批保留程序/数据库备份，以兼容旧 agent 的加法迁移支持渐进发布。

## 5. 补齐边界

可以补齐的主体是账户、额度、实时活动、费用折算、来源统一展示和预算判断。以下数据需要按事实保留限制：

- 历史记录没有账户证据时，真实归属无法自动保证。
- 实际账单、所有云端任务明细和已删除日志，不能仅靠当前本地日志恢复。
- 缺少的缓存 TTL、编辑行数、工具计费与等待状态按能力显示未知，不能为了与 Claude 卡片相同而填零。
- App Server/日志字段随 Codex 版本演进，使用版本样本与契约测试维护兼容。

上述三批的主体已交付；实际可观测范围和未启用能力见第 6 节，生产验收结果见第 7 节。

## 6. 本轮实现与实际边界

账户/成员标识、多配置目录、隔离只读 App Server、通用额度窗口、限额历史、来源筛选、采集健康、查询租约、日志实时状态、缓存写入和费用折算、历史原位补字段、保留去重键、服务端账户活动、budget 和 20 个 MCP 工具已实现。Hook 接入未启用；默认日志观测显示最近活动，不能确认等待审批等细状态。

实际只读联调：MacBook 0.153.4、mini 的 24haowan 用户 0.149.0 返回套餐、通用窗口及 145 个每日桶，原登录文件哈希不变。mini 的 verkyyi、verkydev 凭据已过期；vincent、zx 没有 Codex 目录。服务端总量和本地明细的时区、范围、延迟尚不能证明一致，页面分别展示，不生成误导性的差额或云用量结论。
