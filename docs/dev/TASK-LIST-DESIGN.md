## 两端共同的减法

- 两端列表只分 **PIN / 非 PIN**，PIN 在前；运行、审批、失联、唤醒计划均在行内显示，不作为分组或排序条件。
- 一行对应一个 Task。当前会话更换后仍是同一行；历史会话在该 Task 内查看，原生 Subagent 不展开成 Hub 行。
- 移除父子缩进、EPIC 展开箭头、成员计数、driver 和协调者身份；没有 Batch。
- 只表达当前是否运行。错误、审批、交付结果和下次唤醒是事实说明，不再派生「已完成 / 已取消 / 已落地」任务终态。
- 保留现有打开、搜索、命名、环境和个人入口；不加看板或筛选栏。运行信息来自同一 Task 快照，跨端一致。
- 原生运行情况未知时显示 `?` 和最后观测，不把它当非运行中。普通订阅不等于自动唤醒。

## iTerm2 / tmux：保留紧凑面板

入口仍为 ⌘P；手机 SSH 终端沿用 F12 / ⌃] p。面板之外的键完全属于 iTerm2 和原生 Agent。面板不是常驻侧栏，不变成网页，也不新增全局快捷键。

### 行、分区和说明

现有列顺序原样保留：**图标 1 格 · 短码 8 格 · Agent 7 格 · 标题 · 仓库 13 格**。仍是单行任务，机器、PR、原生会话 ID 等只出现在选中行底部说明或动作页。沿用 Tokyo Night / 现有浅色主题、反白选中和现有对齐规则；不是一张带表头的表格。

顶端「Messages / New session / Shell」三项保留其位置；新建文案调整为「New task」，仍用现有 Agent / 仓库选择页，首条输入作为任务描述，不再加角色、父任务或新建向导。消息只汇总 Hub 事件，不再有「转交给编排」操作。

列表只保留「PIN / 非 PIN」两个分区，PIN 在前。两个分区内都可以同时包含运行中、非运行中、审批中或失联任务；运行变化只更新该行，不移动任务。PIN 是用户偏好，不是身份；用户明确 PIN / 取消 PIN 才跨区移动，选中仍跟随同一个 Task。搜索结果仍保留这两个分区，空区不显示。

每行首图标显示运行事实，标题旁显示原生短状态（如 `active`、`working`、`idle`、`exited`）；需要人时显示 `! 等审批`，观测缺失显示 `?` / `失联`。不另设「Running」「Not running」「Waiting」「Connection unknown」或历史状态分组，也不保留「Older tasks」第三个折叠区。较多任务在同一分区内滚动或加载，既有归档操作仍是明确的列表收纳操作。
除行内状态外，有自动唤醒时在标题尾部加短提示 `↻ 14:30` 或 `↻ 等 A7P4`；不挤掉短码与 Agent。没有计划且观测完整就不加尾标，底部说明明确「不会自动运行」。计划未知显示 `↻ ?`，不能把没有观测当作没有计划。窄宽度放不下完整提示时仍保留 `↻`，选中底部给出完整条件。

### 操作页

选中 → Tab，仍是同一面板中的二级全页，不弹浮窗。顺序为：打开、停止任务、继续工作、改名、切换 Agent、自动运行、产物、会话历史、归档。保留原有可搜索/编号选择方式；不把实现中的 API 参数展示给人。

「停止任务」不再叫「回收」，不要求先合并、先上报、先结束 Subagent 或解除 keep。Enter 即提交，旁边固定一句「停止执行与自动唤醒，保留文件」。重复请求幂等；请求失败留在原页并显示重试，原生回执前不假报已停止。Esc 返回保留选中 Task、搜索和滚动。

宽度 ≥60 列保留仓库；40–59 列藏仓库；小于 40 列再藏 Agent，遵循现有 `row_segs` 的降级方式。中文/emoji 按显示单元截断；不为窄屏把每行变成三行卡片。状态和计划的全文进入选中说明区，该区允许换行。

## Web：沿现有侧栏和对话工作区改

### 桌面

保留现有 `Shell`：左侧列表、右侧网页对话；顶部品牌、额度、搜索图标、＋的位置不变，底部仍是本人和个人菜单。左侧一行仍为图标＋标题，不加表格列，不加五个筛选，也不把列表挪到内容主区。

列表只用「PIN / 非 PIN」两个轻量分隔标题，PIN 在前；每区内保持稳定顺序。行内首图标表达运行事实，标题旁直接显示原生短状态；`! 等审批` 表示需要人，`失联` 表示缺少观测。仅有自动唤醒的行末增加小 `↻` 提示；短码、Agent、环境和状态全文沿用 hover 说明。标题可以截断，但状态和自动唤醒标记保持可见。

所有行平级，移除父子聚合与「已结束 / 更早的任务」折叠分区，不按运行、等待、失联或时间另设分组。详情内提供 PIN / 取消 PIN；移动后保持同一 Task 选中。状态变化不会让行重新排序。
右侧保留会话标题、短码、状态说明、对话内容与输入框。顶部原「详情」按钮保留；在其旁固定显示「停止任务」，不藏入更多菜单、不禁用审批或 Loop 中任务。原网页「终端」切换及 `?view=term` 入口删除；旧链接回到该 Task 的网页对话并给一次迁移说明，不偷偷开浏览器终端。

### 手机

保留现有手机首屏：品牌 / 额度 / 搜索 / 个人入口，PIN / 非 PIN 两段单行列表和右下角「＋ 新任务」。状态直接在行内，与桌面一致。不改成大卡片、不加底部导航。

点行进入独立的网页对话屏，返回恢复列表位置；任务标题处留详情，停止入口始终可达。继续使用当前长按详情 sheet，补上「当前」「之后」和停止操作；同时点入后的详情也可到达，不能把必需操作只藏在长按里。触控目标至少 44 px。

### 详情仍用现有 Sheet

复用当前详情抽屉/底部 sheet，按次序展示：用户原话、当前会话与原生观测、自动运行、直接依赖、最近产物、会话历史。删除 Parent、成员、协调者、批次进度、回收原因及多套任务终态字段。

原生审批仍由原生能力/现有已验证审批通道承接，不在原型里造「批准」按钮。若 Web 暂不支持某个原生交互，明确给出 iTerm2 中打开该 Task 的指引；移除网页终端备份不等于承诺所有原生交互已在 Web 实现。

## 状态与操作的边界

| 场景 | 列表 | 详情 / 选中说明 |
| --- | --- | --- |
| 正在执行，无后续计划 | 运行图标＋标题＋原生短状态 | 运行中 · 不会自动运行；原生状态和活动 |
| 正在等原生审批 | 运行事实图标＋标题＋`! 等审批` | 原生运行事实独立保留，写明等待哪个请求；停止仍可用 |
| idle，已设循环或依赖唤醒 | 非运行图标＋标题＋`idle`＋`↻` | 下次绝对时间与时区 / 指定任务的产物条件 |
| idle，无计划 | 非运行图标＋标题＋`idle` | 不会自动运行；可以明确继续一次 |
| 原生退出、报错或已有交付 | 按当前事实显示非运行 | 展示原生原因和产物，不升级为任务终态 |
| 失联 | `?`＋标题，计划不明则 `↻ ?` | 最后观测；停止只确认已撤销 Hub 授权，远端仍待确认 |

打开只查看/连接，不自动启动回合。继续工作是明确的一次执行，不恢复已经撤销的计划；依赖未满足时不得默默绕过。停止撤销执行、未来唤醒与自动恢复，保留历史和文件；关闭 iTerm2 面板或浏览器只是离开视图。删除数据是另外的破坏性动作。

输入、搜索、滚动和选中状态按 Task 稳定 ID 保存；实时事件不让光标跳到另一行。运行、审批、失联及唤醒计划变化只更新行内内容，不改变 PIN 归属或行顺序；用户显式 PIN / 取消 PIN 后行才跨区移动。后台事件不抢焦点。Web 的标题和原生观测来自同一快照，不另起状态映射体系。

## 实现范围与验收

本次只交设计及原型，不修改运行中的 iTerm2、tmux 或 Web。

1. 先接入共享 Task 快照，修改现有面板投影和 `SessionList` 行数据；不另建列表应用。旧记录缺少计划证据时显示未知。
2. 移除原有父子/EPIC 聚合和完成终态；当前会话与历史以 Task 归并；旧别名仍能定位。
3. 在原动作页/对话页接入最高优先级停止；验证关闭不被回收规则拦截。
4. 删除 Web 终端 UI、旧路由和相关仅用于该备份的传输依赖；保留 iTerm2 的原生 SSH/tmux 连接及网页对话必需能力。逐个核对共享依赖，不能误删原生 Terminal。

原型检查覆盖两端仅 PIN / 非 PIN 分区、行内状态、PIN 切换、状态变化不移动行、iTerm2/tmux 面板布局、动作页/返回、Web 1440/390 的侧栏与手机单行列表、搜索、详情、停止、继续，以及无网页终端入口。HTML 中的按键演示不等于真实 tmux 验收。实现后还需真实 iTerm2 ⌘P、40/80/120 列、原生输入透传、生产 Web 与停机/失联场景证据；不能用原型截图宣称功能上线。

本设计保留现有接入与界面，删掉多余编排和状态表达；不增加组件、角色、导航或常驻服务。权限、数据保留、原生审批与观测缺口继续透明呈现，符合 [产品方向](PRODUCT-DIRECTION.md)。
