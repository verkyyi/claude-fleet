# Task 列表设计：Terminal 与 Web

T970 / NV03 · 2026-10-22 · 设计提案，尚未上线

本页是 [Hub 任务简化方案](HUB-TASK-SIMPLIFY.md) 的界面部分。[可交互原型](task-list-prototype.html) 使用虚构数据，可切换 Web / Terminal，搜索、筛选、查看详情、模拟停止与继续；不连接生产、不执行真实任务。浏览器中的 Terminal 是终端布局演示，真实按键与列宽行为以本文为准。

## 一个列表，一行一个 Task

两端都只有「任务」，没有 EPIC、Batch、父子树、协调者或单独的会话列表入口。一条 Task 可以保留多次会话历史，换 Agent、换环境或重新继续不会多出一行。原生 Subagent 留在原生会话内查看。

默认显示未归档任务；页面打开时按最近交互排序，之后固定顺序。运行事件更新内容，不把用户正在看的行挪走。用户发送输入、手动新建或重新进入列表时可更新最近顺序；后台心跳、token 流和订阅消息不刷新排序时间。搜索/返回保留选择、滚动及筛选；定位绑定 Task ID，不绑定行号或短码前缀。

新建任务只有描述、Agent、环境（仓库可选），不选角色、不选父任务。默认提供明确的「创建并开始」，另可「仅保存」；保存不运行。原型用一键创建固定示例演示列表变化，不代表真实新建表单。

## 每行回答三个问题

| 信息 | 内容与优先级 | 展示规则 |
| --- | --- | --- |
| 任务 | 名称为主，稳定短码辅助识别 | 标题最多两行；全文在详情，搜索匹配标题/短码/环境 |
| 当前 | 运行中 / 非运行中 | 来自原生事实；失联时改写「运行情况未知」，不编造非运行中 |
| 之后 | 无自动运行 / 下次时间 / 等待具体事件 | 主列始终可见；Loop 用「每 30 分钟 · 下次 14:30」表达，不成为状态 |
| 需要你 | 审批、问题或需处理的原生错误 | 独立文字提示，不盖掉当前或之后；未满足依赖不自动等于需要你 |
| 上下文 | Agent、环境、最近活动摘要 | 辅助文字；PR 合并等仅为产物摘要，不用完成勾号替代运行情况 |
| 操作 | 打开、停止 | 打开只查看；停止对运行、定时、等待依赖、审批和失联任务始终可达 |

「当前」和「之后」必须分开：`非运行中 · 每 30 分钟，下次 14:30` 与 `非运行中 · 无自动运行` 不是一回事。审批也保留原生状态：Codex 若仍报告 active + waitingOnApproval，就显示「运行中 · 等待审批」，不能为两端视觉相同而伪造 idle。

文字是完整含义，颜色只是辅助。运行用实心圆/蓝绿，非运行用空心圆/灰，需要你用 `!`/琥珀，观测未知用 `?`。无色终端仍可理解；不把红/绿分别叫失败/完成。运行事实可信度不足时不计入运行/非运行计数，单独显示未知数量。

筛选是同一平面列表上的条件：全部、运行中、非运行中、需要你、有自动运行。条件可能重叠，不是工作阶段、集合或互斥分栏；不做看板。按一个条件筛选，再叠加文本搜索；「非运行中」不包含观测未知。归档是独立可选视图，默认不显示；没有已完成页。

## Terminal：仍从一个总面板进入

沿用 [当前客户端入口](CLIENT.md)：Mac ⌘P；手机终端 F12 或 ⌃] p。面板外的按键属于原生 Agent。布局继续使用全页列表与二级动作页，不加常驻侧栏、嵌套树或悬浮对话框。

宽度 ≥100 列时，三列为任务、当前、之后；Agent/环境放第二行。选中行的底部说明显示完整活动、需要你和操作。长标题先截断，不截掉「无自动运行」或未知提示；用实际终端 cell width 截断中文和 emoji，禁止按字符串长度补齐。

```text
任务                                      + 新建任务
搜索 名称 / 编号 / 环境…
全部  运行中  非运行中  需要你  有自动运行

   任务                         当前           之后
>  NV03  简化 Hub 任务           运行中         无自动运行
   Codex · dev-node · claude-fleet
   K8D2  发布接口变更            运行中 !       无自动运行
   Claude · cloud-1 · api
   A7P4  检查服务可用性          非运行中       每 30 分钟 · 下次 14:30
   Codex · cloud-2 · ops
   M2R9  编写 API v2 界面        非运行中       等 K8D2 的契约 v2
   Claude · cloud-1 · web

NV03 · 正在检查任务状态的读取路径
Enter 打开   Tab 操作   ↑↓ 选择   Esc 返回
```

60–99 列改为每任务两至三行，顺序固定为名称/短码、当前与之后、需要你；隐藏环境列到选中详情。小于 60 列（例如 40 列手机 SSH）堆叠显示：

```text
> NV03 简化 Hub 任务
  运行中
  之后：无自动运行

  A7P4 检查服务可用性
  非运行中
  之后：14:30 · 每30分钟
```

↑↓ 选择；Enter 打开当前会话或历史（没有当前会话也不自动启动）；Tab 进入该 Task 动作页。面板搜索框可直接输入；动作页首项是「打开」，第二项「停止任务」，随后「继续工作」「自动运行…」「查看产物」「会话历史」「归档」。不可用操作给出原因，停止不因任务繁忙而禁用。Esc 逐级返回并恢复选择。空列表与无匹配分别提示「还没有任务，创建一个开始」及「无匹配任务，清除搜索」。

停止采用选中任务 → Tab → 停止任务 → Enter 的明确动作路径，不增加 y/n 确认。页面就在操作旁说明「停止当前执行并关闭自动唤醒，文件保留」。不设会与搜索或原生输入冲突的裸字母删除/停止快捷键。命令行 `fleet ls` 将来也显示同样的当前/之后语义，窄屏不以省略未来运行意图换取紧凑。

## Web：桌面列表与手机卡片

桌面（1440 px）：页首「任务」和「新建任务」，其下搜索及同样的五个筛选；主区平面列表，列为任务、当前、之后、操作。选中时右侧打开约 360 px 的详情面板，列表仍可见。用户始终有行内停止入口，不必先点更多菜单。

手机（390 px）：每行转为一张紧凑卡片，不横向滚动表格。依次是标题/短码、当前与需要你、之后、Agent/环境、打开/停止。筛选允许换行；触控目标至少 44 px。点击打开进入全宽详情，返回保留列表位置。复杂的时刻和事件描述允许换行，不能藏进 tooltip。

详情共享以下顺序：

1. 标题与当前/之后；需要你时紧接显示原生请求摘要和「打开原生会话处理」。列表不提供另造的批准按钮。
2. 当前会话：Agent、环境、原生状态及来源时间；打开连接当前会话，已退出则看历史。原型只展示入口说明，不伪装原生审批功能。
3. 最近活动与产物；每条可追溯源事件。没有产物时显示「暂无产物」，不能显示失败。
4. 自动运行规则、直接依赖及订阅说明；明确「仅收消息」还是「满足条件会运行」。关联任务链接直接打开对应 Task，不显示层级树。
5. 会话历史，按时间列出；只有当前绑定可接收新输入。恢复旧会话要先通过唯一绑定流程，不直接从旧卡片发消息。

原型包含运行、审批、定时唤醒、产物依赖、无自动运行以及失联六种数据，方便并排比较。不提供虚假的聚合进度或原生 token 动画。

## 打开、继续、停止的区别

| 操作 | 行为 | 用户反馈 |
| --- | --- | --- |
| 打开 | 查看/连接，不启动回合，不恢复计划 | 没有会话则展示任务描述和历史 |
| 继续工作 | 明确启动一次回合，取得唯一当前绑定；若正在运行则进入当前会话 | 旧的自动唤醒规则不自动恢复；有尚未满足的依赖先展示原因，再由用户明确选择修改条件或仅这次手动运行 |
| 停止任务 | 立即撤销自动唤醒和恢复授权，再中断执行；不删除数据 | 请求中保持原生观测；收到确认才显示非运行中 |
| 编辑自动运行 | 用户明确设置时间或事件规则 | 展示具体时间、时区/事件，不能只显示 Loop |
| 归档 | 只隐藏/整理记录，不隐式停止或改计划 | 有执行或计划时明确告知仍会运行；活跃/需要你筛选应可发现归档中的此类任务 |

点击停止不再弹确认。只有请求被接受后才能显示「自动运行已关闭」；Hub 请求失败则显示失败原因与重试，保留原状态，不能成功式乐观更新。重复点击幂等。已非运行且无计划时停止返回「没有运行中的工作，自动运行已关闭」，无需拒绝。

节点失联但 Hub 可达：显示「自动运行已关闭 · 远端停止待确认」，原生运行情况仍未知；停止按钮允许重试。Hub 也失联：显示「停止请求未送达」，不可声称已关闭唤醒。断网提示持续可见，不仅弹 toast。原型演示前一种失联；传输失败列为未来验收。

网页关闭、Esc 离开面板、退出 fleet 连接都只离开视图，不停止 Task；按钮用「停止任务」而不是含糊的「关闭」。原生工具审批保留其权限边界，用户停止不依赖审批被批准。

## 更新与可访问性

列表与详情消费同一 Task 快照和事件，不分别推断状态。事件乱序按任务内序号去重，失联时冻结最后可信事实并显示观测时间。启动/停止请求进度是临时反馈，不持久化成新任务状态。详情中的原始状态与列表投影必须能解释彼此。

Web 使用语义按钮、可见焦点、键盘 Tab 顺序和适度的 live-region 操作反馈；不把整个秒刷列表设为 live。需要你与未知不能只靠颜色。Terminal 提供 ASCII/no-color 图例，窗口缩放不丢选中 Task。长标题、无仓库、未知 Agent、首次加载、空列表、请求失败都不能留下空白的状态解释。

## 落点与验收

这是设计切片，不直接改线上列表。未来实现复用 `bin/fleet_view.py` / `bin/fleet-quickopen.py` 的面板、动作与选择保持逻辑，以及 `extras/web-console/src/app/use-tasks.ts` 的数据入口；先改共享 Task 快照契约，再删两端父子聚合和旧终态呈现。CLI、Terminal、Web 不各建一套任务状态解析器。

设计阶段验证：原型在 1440 与 390 宽度可浏览，Web/Terminal 演示共享数据；筛选、搜索、停止、继续和未知反馈可操作。原型截图与交互验证仅证明设计可读，不代表生产功能通过。

实现阶段验收：两端相同 Task 数据显示一致；40/80/120 列终端无中文宽度溢出；真实 ⌘P/F12 与原生键不冲突；手机触控与键盘可用；实时刷新不挪选中行；停止审批/循环/后台任务不被拦；离线与失败反馈准确；旧会话恢复无双跑。按简化方案的生产验收要求留存发布后的真实界面证据。

本设计遵循产品方向：列表直接解释运行与接入情况，原生会话承接工作和审批；不引入新服务、角色或集合；停止与数据保留分开。接口能力按需展示，无法观测就明确说明，不用视觉统一掩盖厂商差异。
