# Fleet 产品方向与设计原则

## 产品定位

Fleet 专门服务中国大陆的开发者与非开发者，解决顶尖 AI 模型与 Agent 服务在国内接入不便捷的问题。

主要覆盖 OpenAI、Anthropic、Google 等厂商的模型与 Agent 服务，包括 Codex、Claude、Gemini，不绑定单一厂商或产品。

竞争对手是其他中转站提供商。Fleet 通过便捷、可靠的接入，减少用户在账号、网络和运行环境上的负担。

**便捷接入是核心价值；持续在线和灵活使用是配套能力。运行环境与上游服务的稳定性优先于功能扩展。**

对外以服务和产品为主线：先讲给谁用、能做什么、怎么开始，用会话、任务、设备、额度这些用户能感知的词。技术架构、开源与自托管是副线，不作为卖点。

## 设计原则

### 1. 最小核心，原生优先

Fleet 是模型与 Agent 服务的轻量接入和托管层。

模型接入优先兼容官方接口；Agent 接入尽量保留原生界面、命令、工具、技能和授权交互。原生能力能够满足需求时，不另建实现。

不默认改变模型行为，不增加强制工作流。

### 2. 非必要能力全部可选

所有非必要扩展和自定义功能，均不默认安装或启用。

优先使用厂商支持的标准配置、Skills、Plugins、Hooks 和 MCP。扩展由用户主动选择，可独立停用和移除，其失败不应影响核心服务。

不默认注入角色、提示词、工具或工作流。只有标准方式无法满足必要需求时，才增加最小自定义实现。

### 3. 稳定优先，简单优先

先保证可靠接入、持续使用和故障恢复，再增加功能。

减少组件、依赖和故障面，不为未来可能的需求提前堆叠系统。新增厂商或产品应逐一验证，不追求覆盖数量而牺牲稳定性。

明确说明中断与恢复状态，不静默重复执行，不静默替换模型或厂商。

### 4. 完整开源，可检查、可复现

代码、部署架构、配置模板和运维方法均应开源，让第三方能够理解、审查和自行部署。

生产凭据与用户数据不公开。托管服务的价值来自接入便利、稳定运行和持续维护；开源是可检查、可自托管的保证，对外介绍时放在次要位置。

### 5. 透明与安全

公开实际使用的厂商、模型、请求路径、数据流向、权限边界、计量收费规则和重要变更。

用户环境相互隔离，凭据妥善保护，管理权限最小化，敏感操作可追溯。安全承诺必须与实际能力一致。

### 6. 按需使用，按量付费

用户按实际需要选择模型、Agent 和运行资源，费用清楚可查。托管服务也可选择自带订阅：用户接入自己的模型订阅时，只为托管与运行资源付费。

具体价格与资源规格后续确定，不固化在产品方向中。

### 7. 数据由用户掌控

托管环境中的用户文件与会话历史持久保存，由用户按需删除，不擅自清理。

模型接入不以保存请求内容为默认要求，必要的计量信息与内容数据分开处理。

不提供备份，明确说明误删和存储故障可能导致不可恢复的数据损失。持久化不等于备份。

## 产品演进边界

近期优先提供原生 Agent 的云端托管，用户从网页（对话、会话）或终端接入，并按实际需求提供模型接口接入。不重做厂商已有的交互体验。

常驻 orchestrator、steward 和 backlog autofill 已移除（EPIC #4333）：编排和管家只是人按需起的会话模板（`spawn agent:orchestrator` / `agent:steward`）。EPIC 等工作流仅作为可选扩展，不成为使用前提。

长期以稳定 Sandbox 为基础，利用厂商 SDK 和标准扩展提供可选的 Role 与托管执行能力，通过 MCP 供其他 Agent 调用。外部 Agent 负责规划与协作，Fleet 负责可靠执行，不重新引入常驻编排层。

各厂商的授权与地区可用性分别处理，技术接入方式不视为已获许可。国内节点只运行 Codex；Claude 等在地区上不可用的服务只在境外节点运行。

## Fleet 与原生 Agent 的最终职责边界

**Fleet 负责在哪里安全运行、如何持续连接；Coding Agent 负责如何完成工作。**
此边界是目标设计，不代表既有实现已经迁移；组件类别仍以 [COMPONENTS.md](COMPONENTS.md) 为唯一来源。

| 能力 | 原生 Agent 负责 | Fleet 负责 |
|---|---|---|
| 工作目录隔离 | 优先使用原生 Worktree 创建、分支与生命周期能力 | 验证所属仓库和用户，记录真实路径与会话绑定，保护持久数据；不重复创建或清理同一 Worktree |
| 历史与上下文 | 对话存储、压缩、原生 resume / fork | 保存精确原生会话 ID、账号环境和节点映射，提供持久化、定位与恢复入口；不另造对话引擎 |
| 工具与扩展 | 原生工具执行、MCP 客户端、Skills、Plugins、Hooks | 分发受控配置，提供 Fleet 专属接入与跨节点能力；不再包装通用工具执行器 |
| 状态与交互 | 原生界面、事件、回合与输入状态 | 薄面板和接入入口；优先消费官方事件，缺失时才保留有界兼容适配，不把屏幕猜测当权威状态 |
| 模型与审批 | 模型、推理强度、会话工具审批与原生权限设置 | 执行平台允许范围和资源准入，不另建冲突的会话策略；平台准入与 Agent 工具审批分别保留 |
| 任务执行 | 计划、拆解、上下文整理及会话内协作 | 提供可靠执行与必要的跨节点协作接口；编排角色、管家和 EPIC 工作流按需选择，不成为开会话前提 |
| 认证 | 在适用的官方流程内完成登录和刷新 | 保持租户归属、必要的凭据代理/隔离和多副本一致性；不能因有原生登录就删除分布式安全职责 |
| 托管与连接 | 不要求 Agent 管理 Fleet 基础设施 | POD/用户隔离、持久存储、SSH/终端连接、重连、资源额度、版本发布与故障恢复 |

### 替换与保留的约束

- 原生优先不是将 Fleet 逻辑搬进一个自定义 Hook 后换名；只有必要、原生缺失的能力才留薄适配。
- 优先验证原生 Worktree，再决定是否还需要 Fleet 的目录预备或进程预热。不得先增加工作目录池、常驻编排或新会话引擎。
- Worktree 只隔离文件修改，不是安全沙箱；POD、用户、凭据隔离与 CPU/会话额度等准入不能由它替代。
- 同一资源只设一个生命周期所有者。原生管理的 Worktree 不由 Fleet 命名扫描器再次回收；未提交/未推送工作、历史与旧会话不能在迁移中丢失。
- 共享原生后台不等于共享会话身份。会话级能力凭据、终端定位和角色不能放进共享后台环境后假定随客户端切换；必须保留原生线程与平台准入/所有权的可验证绑定。线程 ID 用于定位，不代替授权；绑定未验收前不合并既有私有后台。
- 草稿预填必须仍是「输入框可编辑、尚未发送」。原生启动 prompt 或提交 API 不自动等价于未发送草稿；未验证前不能据此删除兼容逻辑或自动按 Enter。
- 不为统一两种 Agent 而重造其能力；按目标安装版本逐项验证，不把桌面版、CLI、SDK 或上游最新版混为一谈。
- 不自动修改用户已有模型设置、完整 MCP 配置、订阅范围、信任和审批策略。对历史配置和会话保留明确兼容路径。

### 演进顺序与验收

按「原生 Worktree 验证 → 删除重复启动准备 → 原生事件替代重复轮询」分批推进。
每批列明删除项、保留项、兼容条件、失败回退和测量结果；具体盘点与验收见
[原生 Agent 边界迁移](NATIVE-AGENT-BOUNDARY.md)。

先在隔离夹具与 drill 验证，再经 CI、正常发布和真实终端面板验收推广到用户 POD。
计时以同一节点、仓库和配置下的直接原生启动为基线，分别记录派发、准入、仓库同步、目录准备、窗口、输入框、未发送草稿与回复。
提前显示一个空窗口不算提速完成；文档、help、单测或 CLI 探针通过也不等于真实面板验收通过。

## 设计判断标准

每项新设计都应回答：

- 是否直接改善大陆用户的接入或服务稳定性？
- 是否可以复用官方接口、原生能力或标准扩展？
- 是否必须进入默认核心，还是应当可选？
- 是否增加了不必要的复杂度和维护负担？
- 是否符合开源、透明、安全与用户数据自主的原则？

**本文用于约束后续产品方向，不规定具体技术架构、定价或实现方案。**
